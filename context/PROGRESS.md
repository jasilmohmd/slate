## v2 — after the deadline

The hackathon clock is no longer the constraint, so these are numbered
rather than timeboxed. Ordered by leverage and risk, one commit each.

- v2 step 1: Done. Removed the raw streaming HTML `<pre>` from the builder — teachers do not write code, so the artifact source was noise rather than progress. Replaced with a single pulsing plain-language line ("Drafting your material…" / "Checking it works…" / "Fixing a few things…") handing off to the existing checks list, which is where the concrete progress already lived. Deliberately departs from §5c's own mockup, which shows a "streaming artifact source" panel. UI-only: `streamedText` was fed solely by `onDelta` and read by nothing in the generate/verify/repair flow.
- v2 step 2: Done. `src/lib/models/router.ts` implements §5b's per-job routing table as `chooseModel(job, ctx)`, replacing the single hardcoded `GENERATION_MODEL` constant. Vision takes no context override, so "never Luna for vision" is structural rather than conventional; since a photo rides on the generation call itself, that call routes as vision. Landed as a pure refactor — with no env override every job still resolved to `gpt-5.6-sol`, matching the previous constant exactly.
- v2 step 3: Done. Ran §5b's Terra-vs-Sol measurement, which could not be run during the hackathon because Tier 1 did not exist yet at step 3. Split in two, since Tier 1 is client-side by mandate and §5a forbids a headless browser: `scripts/measure-terra.mjs` generates candidates to disk (resumable, and retries transport failures so infrastructure noise is not scored as model misses), and the dev-only `/measure` page scores them with the real, unmodified `runTier1`. **Terra scored 10/10 first-pass**, well clear of the 70% threshold, so `SLATE_GENERATION_MODEL=gpt-5.6-terra`. Caveats: one concept, one language, and scored against the corrected scene-aspect check below — the same batch scored 0/10 against the old one. Prompt-prefix caching confirmed rather than assumed (9005 of 9008 input tokens cached after the first run).
- v2 step 3a (unplanned, found during step 3): Done. **`checkSceneAspect` was wrong and is fixed.** It asserted `container aspect >= data-min-aspect`, but §2a says a container falling below the declared minimum is the condition that *triggers* reframing ("reframe, never squash") — the normal state of any phone in portrait. Every artifact that declared an honest minimum failed, including the checked-in reference artifact (0.69 against a declared 1.2), while the only artifact in the database that ever passed declares `data-min-aspect="0.65"`. It now tests what the spec actually forbids — the rendered SVG no longer matching its own viewBox ratio — plus §2d's requirement that the declared `data-intrinsic-aspect` match that viewBox. `data-min-aspect` stays in the §2d contract and drives each artifact's own reframe logic; Tier 1 no longer asserts on it. Regression case: the reference artifact scores 1/1 through the real `runTier1`.
- v2 step 4: Done. The generation record now absorbs every correction (§2c). `record.corrections[]` added to the existing `jsonb` column (additive, no migration), and `/api/persist-generation` switched from `.insert` to `.upsert` on `id`, so a correction round rewrites the same row: `artifact_html` holds only the latest document, history lives in the record. The client sends the whole corrections array each round, keeping the route stateless. Verified by round-tripping a test row through the live route — insert then upsert with two corrections produced one row with the latest HTML and both corrections intact; test row deleted.
- v2 steps 5–7: Done. **Correction by pointing** (§5 step 3), never built during the hackathon. Element selection uses a `postMessage` shim injected into the preview (`src/lib/artifact/selectionShim.ts`), mirroring `injectErrorShim`. The preview iframe deliberately keeps `sandbox="allow-scripts"` with no `allow-same-origin`. Generation and every correction now share one `runVerifiedRound` helper, so a correction can never quietly ship an artifact that breaks the §2d contract. Corrections are uncapped; repairs stay capped at 3. Luna triages each correction as simple or complex and feeds `chooseModel`. Verified against the live API: a correction asking for a narrower slider range was classified "simple", routed to Terra, changed `max="60"` to `max="24"` on the targeted control, left the sibling control byte-identical and the control set unchanged, and the corrected artifact still scored 1/1 through the real `runTier1`. Classifier agreed with manual judgement on 7/7 comments and fell back to "complex" with no API key.
- v2 step 8: Done. Prompts are a real `messages` array rather than one flattened string. `STATIC_PREAMBLE` is the whole of the first message and never varies, so the cacheable prefix is byte-identical across generation, repair and correction; earlier turns collapse to `[corrected: <comment>]` placeholders instead of replaying documents. No server-side session store — the thread is reconstructed per call from the corrections the client already holds. Measured over a 3-correction session on Terra: the thread grows about 47 tokens per correction (17088, 17134, 17182) and a warm cache covers 17085 of 17088 input tokens, against 32730 tokens by round 3 if the prior documents are replayed in full. Structurally, exactly one full document appears at any history depth (checked at 0, 1, 3 and 10 corrections).
